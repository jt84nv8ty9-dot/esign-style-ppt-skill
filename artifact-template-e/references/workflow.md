# 制作、替换与检查

默认先设计内页信息结构，见 [灵活内页设计](interior-design.md)。本页1–3节介绍的 `deck.py build` 仅用于原页换字或搭建初始框架，不是整套新主题稿的默认排版方法。重排内容区时使用第4节；不要因换字脚本方便而放弃新布局。

## 运行环境

辅助脚本只依赖Python 3.9+标准库，不依赖python-pptx，也不包含本机绝对路径。命令均从skill目录运行，或改为脚本的完整路径。用 `python3`（Windows可用 `py -3`）。脚本不负责渲染，渲染使用已有的Presentations/PowerPoint能力。

## 1. 查看原型槽位

```bash
python3 scripts/deck.py slots --slide 4
```

输出包含源页、共用布局、标题shape ID、可改文字shape ID、原文和坐标（英寸）。ID只在对应源页内有效。`references/slots.json` 为完整索引，可搜索原文定位。不要从截图猜ID。

## 2. 编写新内容规格

制作任务中的 `content.json` 是**生成PPT的文字内容输入**，与创建/安装模板本身无关。按以下格式组织：

```json
{
  "slides": [
    {
      "source": 1,
      "replace": {
        "3": ["企业数字信任", "解决方案"],
        "4": "让签署与合同管理连接业务",
        "6": ["演讲嘉宾：张某", "2026年11月 · 杭州"],
        "7": ""
      }
    },
    {
      "source": 4,
      "title": "企业合同管理的四项需求",
      "replace": {
        "16": "统一流程和责任，让合同处理更清晰",
        "20": "身份可核验",
        "21": "在签署前明确参与方与授权范围",
        "23": "流程可追踪",
        "24": "记录发起、审批、签署与归档状态",
        "26": "内容可管理",
        "27": "按业务规则整理合同版本和关键信息",
        "29": "系统可连接",
        "30": "让签署与已有业务系统保持协同"
      }
    }
  ]
}
```

- `slides`的长度即总页数；必须首选原第1页封面，后续可重复选内容原型，原第18页仅在需要结束页时选。
- `source`是原稿页码。普通内容页的`title`必填，脚本自动用原第4页的完整标题样式覆盖该原型的大标题。标题应一行，先精简文本。
- `replace`的键为形状ID，值为字符串或段落字符串数组。段落样式继承对应原段落；超出原段落数时继承最后一段。脚本合并段内碎片run，保留该段首个run样式，**不保留段内多种混合字重/大小**。例如指标“96%”的大小层次需要分对象或使用专业编辑工具修复，不能声称脚本保留所有富文本。
- 封面仅允许ID 3、4、6、7四个文本框。字符串中的换行或数组明确控制段落；图片和标识不可替换。
- 所有原有非空文字都必须出现在`replace`或`keep`中。`keep:["某ID"]`表示明确原样保留该shape的文字、格式和事实，不是忽略它。不得为了绕过校验自动将所有旧文字加入keep。
- 源页2、3、6有业务截图、证书/图表、视频，只有已确认这些原素材仍适用时设置`allow_source_assets:true`。否则改用其他原型或通过专门工具替换媒体/图表后检查。
- 文字超长不会被脚本自动缩字号，必须渲染检查。这避免破坏统一字体，但不保证无溢出。

## 3. 生成与审查

```bash
python3 scripts/deck.py build content.json 输出.pptx
python3 scripts/deck.py audit 输出.pptx
```

输出路径必须不存在，防止覆盖。脚本完整保留源稿，生成新的PPT包。它复制源幻灯片对象和共享资源，去掉生成页原有备注，不把旧演讲备注带入新主题；删除新包中不再可达的原页和媒体。共用母版/布局及其依赖保留原字节。原型中的图表部件可能被多个复制页共用，因此**重复原生图表后若要不同数据，必须克隆其图表和工作簿部件，再分别改数值**，本脚本不执行此操作。

不要把结构检查说成全面视觉审核。`audit`仅检查：

1. 源画布尺寸未变化；
2. 首页面非文字对象未变化、四个文字框的基础样式和字号未变化；
3. 源封面关联的母版/布局/资产字节未变化；
4. 内容页仍指向布局2；
5. 内容页存在一个标准标题、显式run字号30pt；
6. 包内关系可解析。

随后渲染全稿，检查小标题、正文、数字层次和字体可用性。图表/表格应可编辑，媒体关系应有效。源内容页的普通shape命名很泛化，不能仅按“TextBox”判断角色。

## 4. 需要新增排版或编辑图表

保留源母版/布局和封面，再用Presentations或其他原生PPT编辑工具操作内容区。复制标准标题后，可移除原卡片、色带及无关对象，按内容新建图文、流程、矩阵、关系图或图表；无需保留原模块数量、坐标和比例。删除对象时检查连接线、动画与媒体关系，新增部件使用无冲突ID。保留可编辑文本、图表、表格，不把内容页整体截图化。新数据图表显式设微软雅黑和模板紫色系。若导入工具重写共享母版或背景，必须恢复源部件并检查，不能以“看起来差不多”替代封面锁定要求。

可先用脚本组装源页框架，再编辑内容区；全页重建工具如无法保留原封面，可以先生成内容，最后将原封面及其完整依赖无损合并，但必须解决关系ID和部件路径冲突，不直接拷贝一段slide XML就结束。

## 5. 交付前人工检查

- 封面四字段已更新，主标题两行且未挡右侧插画；原活动信息无残留。
- 普通内容大标题统一一行30pt，背景及左上标识一致；结束页66pt例外只用于结束。
- 卡片正文无越界和挤压；长英文不出现异常一词一行；每张案例的痛点与方案对应。
- 品牌配色一致，紫色重点面积按信息调整；背景与标识保持可见，不使用Office默认配色。
- 整套构图有合理变化；卡片与底部色带只在合适页面出现，不把三栏换四栏视为已充分丰富布局。
- 新主题涉及的数字、认证、客户、案例、日期均有新材料依据。缺失信息不编造。
- 目标机器字体与视频可用。必要时附PDF供预览，但不能用PDF替代用户要的可编辑PPT。
